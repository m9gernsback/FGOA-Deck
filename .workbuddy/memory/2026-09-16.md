# 2026-09-16

## 排查：从 Steam 拉起 FGOLocalPlatform.exe 后游戏无法启动（inject 报 "DLL failed to load inside target process"）

- 报错含义：inject.exe 用 CreateRemoteThread(LoadLibraryW) 向挂起创建的 ago.exe 注入 fgohook.dll，LoadLibrary 在目标进程内返回 NULL（DllMain/pre_startup 主动失败），inject 随即杀掉 ago.exe → "crashed after 0.6 seconds (exit 1)"。
- 排除项：ago.exe/fgohook.dll/inject.exe 均为 x64；fgohook 静态依赖（XINPUT1_4/VCRUNTIME140/UCRT 等）齐全；App 目录下所有 DLL 架构正确；三个关键二进制与 v1.02 更新包哈希一致；ago.exe PE 时间戳校验 (0x643f4ecd) 通过。
- 反汇编 fgohook.dll 定位："Resolution mode: native-surface patch failed (hr=80070057)" 的唯一来源是分辨率配置结构体 width/height <= 0（E_INVALIDARG）。结构体来自 segatools 配置 [gfx] width/height。
- 关键机制：FGO_Launcher.ps1 会把 App\segatools.ini 复制为 DEVICE\runtime\segatools.runtime.ini 并写入 width=1280/height=720，再通过环境变量 **SEGATOOLS_CONFIG_PATH** 传给 inject/fgohook。手动跑 inject 时若漏掉该环境变量，hook 会读到 App\segatools.ini 里的 width=0/height=0 → 必然 E_INVALIDARG（这是复现时的坑，不是真故障）。
- 验证：补齐环境后手动 inject 成功；用 PowerShell 直接跑 FGO_Launcher.ps1（与平台完全同链）也成功，ago.exe 正常进入游戏（12:49）。甚至把 Steam 的 gameoverlayrenderer64.dll 排在 fgohook 之前注入也能正常启动。
- 结论：游戏本体、hook、launcher 全部正常，故障只在 "Steam → FGOLocalPlatform → … → ago.exe" 这条进程树中出现。最可能是 Steam 覆盖层(overlay)对子进程树的 CreateProcess 注入与 inject.exe 的"挂起创建+入口劫持"调试注入发生竞争（提前恢复 ago.exe 主线程）。
- 处置建议：Steam 中右键该游戏→属性→关闭"在游戏中启用 Steam 覆盖"，并把 Steam 输入设为禁用；或干脆不经 Steam、直接用 FGOLocalPlatform.exe 启动。
- 复现脚本要点：cd App 目录，设置 SEGATOOLS_CONFIG_PATH=DEVICE\runtime\segatools.runtime.ini 及 FGO_* 图形环境变量，运行 `inject.exe -d -k fgohook.dll -k zh\fgozh.dll ago.exe -hdtv720 -w --wasapi-shared`，可绕过平台直接看到 ago.exe 内 pre_startup 的完整输出（比平台日志详细得多，平台经 PowerShell transcript 会丢失 stdout）。
