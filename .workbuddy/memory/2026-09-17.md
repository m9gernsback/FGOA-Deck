## WSL+Bottles 实测结果（WSL 内 CodeBuddy 执行完成）

### 环境侦察
- 默认 GL：llvmpipe 软渲染（WSLg 默认）。
- `GALLIUM_DRIVER=d3d12` + `MESA_D3D12_DEFAULT_ADAPTER_NAME=NVIDIA` → `D3D12 (NVIDIA GeForce RTX 5080)`，转译层工作正常。
- **bindless 扩展数 = 0**：Mesa-d3d12 不提供任何 `GL_NV_bindless_*` / `GL_ARB_bindless_texture`（无论强制哪块 GPU）。

### 服务器（Linux 原生，已验证可用）
- MariaDB 10.11 (apt) 直接挂载 Windows 版 datadir（`Server/data/mariadb`，跨平台兼容），端口 8888，`aime/FgoLocal2026` 连通。
- ARTEMiS 跑在 `~/fgoa-server/venv-linux`（需额外 `pip install msgpack`，requirements.txt 未列）；777/9999/7777 全部监听，`http://127.0.0.1:777/` 返回 `Service OK`。
- 坑：HTTP 端口 777 < 1024，需 `sysctl -w net.ipv4.ip_unprivileged_port_start=0`；`dns.default=192.168.100.1` 需 `ip addr add 192.168.100.1/32 dev lo`。

### Bottle / 启动链
- Bottles flatpak 只能 --user 安装；`bottles-cli new --runner ge-proton` 是字面目录名会失败，实际 runner 为 **soda-11.0-10**（Wine 11.0）。DXVK 已关。
- 游戏文件 26G 复制进 `~/.var/app/com.usebottles.bottles/data/bottles/bottles/FGOA/drive_c/FGOA`，ago.exe md5 与源一致。
- 宿主直接跑 runner wine 需 32 位库：`dpkg --add-architecture i386` + libc6:i386 等（否则 `/lib/ld-linux.so.2: could not open`）。
- 启动脚本 `~/fgo-launch.sh` 1:1 复刻 ps1（runtime ini 改写、UTF-16LE BOM、amdaemon_main.json、player.json、全套 FGO_* 环境变量、FGO_DECK_CHANNEL）。

### 核心结论（按方案 §6 模板）
- GL renderer：`D3D12 (NVIDIA GeForce RTX 5080)`（强制后）；**无 NV/ARB bindless 扩展**。
- inject.exe 注入：**成功**。fgohook.dll 全部子系统初始化完成（vfs/netenv/aime/printer/deck/LED/GP lock/协议诊断/时钟/战斗补丁），`fgo_pre_startup` 完成，amdaemon 由 ago.exe 正常拉起，窗口 1280x720 创建成功。
- ago.exe 走到：窗口创建 → GL 上下文初始化 → **`wglGetProcAddress("glGetTextureHandleARB")` → Wine 警告 `Extension GL_ARB_bindless_texture ... not supported` → 返回 NULL → 数条 GL 调用后 0xc0000005 访问 0x0 崩溃**（dump: logs/ago-crash-20260917-152605.dmp）。
- **结论：失败点精确命中方案 §0.2 预测——WSL GL 转译层缺 bindless，不是注入链/Wine 兼容性问题。转真 Linux（原生 NVIDIA 驱动）重测，§3~6 全部可复用。**
- 次要问题：`zh/fgozh.dll` 在 Wine 下 DllMain 于 REDIRECT_INDEX(files=1451，数量正确) 之后返回 FALSE 卸载（Windows 正常）；中文资源 hook 需单独排查，不影响 GL 结论。复现：`WINEDEBUG=err+all,+loaddll FGO_ZH_DLL=1 bash ~/fgo-launch.sh`。
